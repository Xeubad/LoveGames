# 前端规则

本文件只负责前端界面和视觉约束，不负责人格路由。

## 核心原则

- 功能优先美学：所有视觉设计必须服务于功能实用性。
- 单一令牌来源：颜色、圆角、阴影、间距、字号只在 `src/shared/styles.css` 的 `:root` 里定义一次。
- 系统一致性：所有游戏共用同一套结构语言，只有主题色不同。

## 风格方向

- 定位是情侣向产品，保留浪漫渐变态，不走企业级冷淡风。
- 渐变只允许通过令牌使用（`--lg-gradient`、`--lg-accent`、`color-mix(...)`），不在组件里手写色值。
- 大厅（游戏选择页）深色底，进入具体游戏后统一浅色底。
- 阴影分三级（`--lg-sh-1/2/3`），只用于层次区分，不堆叠。

## 硬性约定

- **组件内不写死颜色、圆角、阴影、间距、字号**，一律用 `var(--lg-*)`。
  例外只允许两类，且必须是「一次性、无跨组件复用价值」的：
  棋盘内部的半透明叠加层（如 `rgba(255,255,255,.22)` 的格子）、
  以及起点/终点格这类只用一次的语义色。渐变上的文字用 `--lg-on-accent`。
- **主题色只由 CSS 主题类提供**：`.theme-<游戏id>` 定义在 `styles.css`，
  游戏页面在自己的根元素上挂 `lg-shell theme-<id>`。`server/games-registry.js` 不存颜色。
- **导航统一走 `src/shared/GameToolbar.vue`**：sticky 顶栏，占据布局空间，
  在游戏区域之外。禁止把返回按钮绝对定位到游戏画布内部。
- **优先复用共享组件类**，不要各页面各写一套：
  `lg-btn`（primary/ghost/quiet/sm/block）、`lg-card`、`lg-badge`、`lg-source`、
  `lg-notice`（ok/warn/danger）、`lg-modal`、`lg-segment`、`lg-switch`、`lg-field`。
- **状态三态必须分得开**：加载中 / 空数据 / 请求失败不能渲染成同一个样子。
- **来源如实标注**：AI 生成与本地题库要用 `lg-source` 明确区分，降级时说明原因，
  不允许把本地内容显示成 AI 结果。

## 执行规则

- 新增 UI 前先确认功能目标和信息层级，而不是先做视觉包装。
- 新增游戏时：在 `styles.css` 加一个 `.theme-<id>` 块，页面根元素挂上对应 class，其余全部复用共享类。
- 窄屏（≤640px）必须可用：飞行棋的控制台在窄屏要从棋盘中心移到棋盘下方，
  棋盘用 `aspect-ratio: 1` 保持正方形，不随视口拉伸变形。
